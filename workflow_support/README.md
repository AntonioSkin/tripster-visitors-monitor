# Независимое выполнение четырёх задач

У каждой задачи собственная очередь `tripster-task-1` … `tripster-task-4`.
Она охватывает весь workflow, включая сохранение данных: два запуска одной задачи
не читают одно старое состояние одновременно и не дублируют уведомления.

Долгий сбор и отправка отчёта проходят в независимых заданиях. Изменённые данные
и отметки доставки сохраняются в неизменяемый artifact на 14 дней. Короткое задание
записи получает свежую `main` и вносит только файлы своей задачи. Только эти задания
используют общую очередь `monitor-results-write`, с `queue: max`.
Группа задачи и группа записи намеренно различаются.

При конкурентном изменении `main` запись подтягивает новую версию и повторяет
попытку до 5 раз. Force push не используется. Если уже изменился тот же файл,
автоматическая перезапись запрещается. Повтор только задания `save` использует
исходное имя artifact из outputs сбора и не отправляет Telegram заново.

Резервные проверки вынесены из Daily visitors. Быстрый workflow Backup monitoring
dispatch просыпается каждые 20 минут, проверяет фактическую необходимость и запускает
исходные workflows через workflow_dispatch. Если задача уже запущена или ожидает,
дополнительный запуск не создаётся. Это резерв внутри GitHub, а не внешний
автоматический перезапуск от Healthchecks.

Healthchecks подтверждает успех только после сохранения данных. При сбое сбора
или записи срок не продлевается. Задача 2 по-прежнему отправляет в основной чат
только полезные уведомления, а технические тревоги — через Healthchecks.

## Откат

Состояние до изменения сохранено в ветке
`backup/shared-queue-8d2de4e6`, коммит `8d2de4e69403f92850ffb4c7bc085efa0b6db88e`.

Для отката дождаться завершения активных сборов и записей. Восстановить из этой
ветки **только четыре файла** `daily.yml`, `seats.yml`, `calendar-history.yml`,
`fx.yml` в `.github/workflows/` и удалить `backup-monitoring.yml`.
Сохранить это обычным новым коммитом поверх актуальной `main`.
Данные, таблицы, отметки доставки и ветку `monitor-health-state` не откатывать.
Не перемещать `main` назад и не применять force push.

Вспомогательные writer и tests могут остаться: восстановленные workflows их
не вызывают. Healthchecks и отключение дублей служебных сообщений задачи 2
сохраняются. Для возврата к независимому режиму восстановить файлы из коммита
с сообщением `Enable independent task execution with serialized result writes`.

## Проверка

`python -m unittest workflow_support.test_persistence workflow_support.test_dispatch workflow_support.test_workflows -v`

Проверяются два набора данных от одной исходной версии, сохранение чужих изменений,
повтор после движения main, защита от перезаписи более свежего результата,
повторная запись без нового коммита, корректные резервные запуски и группы очередей.

GitHub может задерживать или пропускать сами cron-события; изменение очередей
не даёт гарантии запуска ровно по часам. Сроки контролируются независимо Healthchecks.

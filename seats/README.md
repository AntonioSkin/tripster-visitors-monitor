# Мониторинг свободных мест — 51584

Отдельный скрипт: python -m seats.monitor. Отдельный workflow: Tripster seat alerts.
Проверки запланированы каждые 30 минут, круглосуточно. GitHub Actions может задерживать или пропускать запуск.

- Период: сегодня и следующие 29 календарных дней по часовому поясу экскурсии (Алматы).
- Уже начавшиеся выезды исключаются; даты без выезда не считаются нулём.
- Источник: ответ /api/web/v1/experiences/51584/schedule/, который получает публичная страница.
- available_persons — свободный остаток. booked_persons из него повторно не вычитается.
- Если слот не задаёт available_persons, используется defaults.available_persons того же ответа.
- Уведомление при 0–6 местах, включая первый обнаруженный низкий остаток.
- Тот же остаток на ту же дату и время повторно не отправляется. Изменение низкого остатка вызывает новое сообщение.
- После восстановления до 7+ мест последующее падение снова вызывает сообщение.
- Исчезновение даты не означает распродажу: явный ноль обнаруживается, скрытый выезд не подменяется нулём.
- При ошибке — одно сообщение за непрерывный сбой, затем сообщение о восстановлении.
- Используются существующие TELEGRAM_BOT_TOKEN и TELEGRAM_CHAT_ID. Вместимость автоматически не меняется.
- После первой успешной проверки приходит сообщение о включении либо список низких остатков.
- Данные: data/seats/latest.json, статус: data/seats/status.json, подтверждённые уведомления: data/seats/state.json.
- Отчёт: reports/seats.md. Ошибка отправки не помечает уведомление доставленным.
- Состояние сохраняется после подтверждения Telegram. Редкий сбой между отправкой и сохранением может дать дубль.

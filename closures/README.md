# Задача 5 — мониторинг закрытия мест конкурентов

Экскурсии берутся из состава задачи 3: Юлия — 51192, 96862, 53900;
Дмитрий — 57434, 85543, 55575, 54971. Каждый календарь проверяется отдельно
на сегодня и следующие 29 дней, для каждого опубликованного времени выезда.

Запуск `Competitor seat closures` запланирован каждые 30 минут.
Резервный диспетчер повторяет запуск, когда данные старше 25 минут и нет активного запуска.
Сбор независим от задач 1–4; только сохранение результатов использует общую короткую очередь.

Оповещение: наблюдавшийся положительный остаток сменился явным нулём.
Первый замер и новые даты сохраняют исходные значения без тревоги.
Неизменный ноль повторно не уведомляется. После открытия мест новый переход
на ноль снова уведомляет. Исчезновение даты или времени не подменяется нулём;
последнее известное значение сохраняется до выезда. Прошедшие выезды исключаются.

Уведомление содержит название, гида, номер экскурсии, дату, время и изменение,
например `30.10.2026 в 06:00: 5 → 0 мест`. Оно не утверждает причину закрытия.
Остатки у конкурентов и собственные места скрипт не изменяет.

`data/closures/<id>/latest.json` — последний календарь;
`state.json` — предыдущие значения, очередь неотправленных событий и последний успех;
`alerts/YYYY-MM-DD.json` — подтверждённые уведомления;
`status.json` — результат сбора и отправки.
Корневой `completed.json` обновляется только после успеха всех семи экскурсий
и отправки всех ожидающих уведомлений. Без изменений обычных сообщений нет.

Событие сохраняется до отправки и не теряется при ошибке Telegram. После
подтверждения оно удаляется из очереди. Как и в остальных задачах, редкий
таймаут после фактической доставки или сбой сохранения может вызвать дубль.

Healthchecks контролирует задачу 5 отдельно: период 30 минут плюс 60 минут
на повторы. После 90 минут без нового полного успешного сбора приходит тревога
в отдельный чат Healthchecks; после восстановления — сообщение от Healthchecks.
Неполный сбор или неотправленные события не подтверждают успех.

Проверки: `python -m unittest closures.test_monitor -v`.
Ручной запуск: Actions → Competitor seat closures → Run workflow.
Для отключения задачи восстановите предыдущую версию workflow и резервного
диспетчера; данные остальных задач и история сохраняются.

# Мониторинг посетителей Tripster

**[Последний отчёт](reports/latest.md)** · **[История CSV](data/daily.csv)** · **[Запуски](https://github.com/AntonioSkin/tripster-visitors-monitor/actions/workflows/daily.yml)**

Сбор счётчика «посетили» для экскурсий **51192, 54971, 57434, 96862, 55575, 53900, 85543**.

## Расписание
Утреннее окно **08:00–10:00 по Алматы**. Часовой пояс явно задан как Asia/Almaty.
Попытки запуска: 08:07, 08:27, 08:47, 09:07, 09:27, 09:47.
После подтверждённой отправки сохраняется отметка data/telegram/YYYY-MM-DD.json; остальные попытки за день пропускаются.
Проверка фактического местного времени выполняется до сбора и перед отправкой: задержавшийся автоматический запуск после 10:00 не отправляет сообщение.
GitHub допускает задержку и пропуск запланированных запусков; доставка в окне не гарантирована при сбое планировщика.
Ручной запуск: Actions → Daily visitors → Run workflow.

## Источник данных
Скрипт открывает публичную страницу каждой экскурсии в Chromium и читает ответ, который запрашивает сама страница: поле **visitors_count** в /api/web/v2/experiences/{id}/.
Проверяется ID экскурсии и тип счётчика. Общий счётчик гида не используется.
Отдельный запрос к API без контекста страницы возвращает 401, поэтому скрипт использует обычную загрузку страницы. Логин, скопированные токены и поисковые копии не используются.
Изменения сайта могут потребовать доработки. Данные актуальны на время ответа Tripster; внутреннее обновление счётчиков зависит от сайта.

## Отчёты
- По каждой экскурсии: число посетивших, время чтения и ссылка.
- Общая сумма выводится только при успешном сборе всех выбранных счётчиков.
- Прирост — разница с предыдущей календарной датой. «—» означает отсутствие сравнимого замера.
- Все попытки: data/runs. Ежедневные снимки: data/daily. Таблица: data/daily.csv.
- Ошибки не заменяются нулями; неудачный повтор не стирает успешный дневной снимок.
- Повторные успешные запуски в один день обновляют дневной снимок, но все попытки сохраняются.

Сумма — посещения выбранных экскурсий, а не уникальные люди. Прирост счётчика не подтверждает фактическое число посетителей именно за сутки. Уменьшения сохраняются как корректировки.

6 октября 2026 года сбор не удался: числового замера за эту дату нет. Значения со скриншотов задним числом не подставляются.

## Изменить список
Отредактируйте excursions.json. Не добавляйте одинаковый ID дважды.

## Локальный запуск
Python 3.12:
```sh
pip install -r requirements.txt
python -m playwright install chromium
python -m unittest -v
python monitor.py
```

## Telegram
Отправка подготовлена и включается после добавления **обоих** секретов в
[Settings → Secrets and variables → Actions](https://github.com/AntonioSkin/tripster-visitors-monitor/settings/secrets/actions):
- TELEGRAM_BOT_TOKEN — токен бота от [BotFather](https://t.me/BotFather).
- TELEGRAM_CHAT_ID — числовой ID вашего личного чата с ботом.

Создайте бота командой /newbot у BotFather, затем откройте созданного бота и нажмите Start.
ID можно получить из message.chat.id в ответе метода getUpdates вашего бота
(https://core.telegram.org/bots/api#getupdates). Токен храните только в Secrets, не в файлах и не в обсуждениях.
Для проверки запустите Actions → Daily visitors → Run workflow.

Сообщение содержит семь счётчиков, сумму и изменения к предыдущей календарной дате.
Отправляется снимок именно текущего запуска, включая частичные ошибки; старый успешный отчёт не подставляется.
Расписание и повторные попытки описаны выше. Изменения кода запускают только проверки, без отправки.
Ручной Run workflow допускается вне утреннего окна, но тоже не отправляет повторно при наличии отметки за сегодня.
Без обоих секретов рассылка ещё не активна. Если задан только один — шаг завершится ошибкой.
Ошибка отправки не удаляет собранные данные. Без отметки об успешной доставке следующая утренняя попытка повторит сбор и отправку.
Редкий сетевой таймаут после фактической доставки или сбой сохранения отметки может привести к дублю: Telegram не предоставляет ключ идемпотентности для sendMessage.
Если сбор аварийно завершился до создания снимка, сообщение не отправляется — проверьте Actions.
Если обновления прекратились, проверьте Actions: GitHub может отключать расписания в публичных репозиториях при длительном отсутствии активности.

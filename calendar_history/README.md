# Задача 3: история остатков Юлии и Дмитрия

Замеры ежедневно каждые три часа: **08:00, 11:00, 14:00, 17:00, 20:00 и 23:00 по Шымкенту (Asia/Almaty, UTC+5)**.
Новое расписание действует с 20:00 02.11.2026; дополнительные прошедшие интервалы не создаются задним числом. С 03.11.2026 выполняются все шесть замеров.
У задачи 4 по курсу остаются отдельные часы 11:00 и 20:00.
Резерв и внутренний контроль используют новый график. Внешний Healthchecks пока остаётся на прежних 11:00 и 20:00: его настройки не изменены.

Юлия: 51192, 96862, 53900. Дмитрий: 57434, 85543, 55575, 54971. Читается весь опубликованный календарь Tripster, без ограничения 30 днями. Закрытое время не считается продажей; изменения сравниваются с предыдущим успешным замером.

Каждый интервал имеет отдельный `observation_id`, например `2026-11-03T08:00` или `2026-11-03T23:00`. Снимки семи экскурсий сохраняются в `measurements/{observation_id}.json`; исходные ежедневные снимки в `daily/` остаются архивом.
CSV `history.csv` содержит все замеры, `summary.csv` — последние остатки. Объединённые таблицы расположены в `data/calendar_history/yulia/` и `data/calendar_history/dmitry/`.

Последняя колонка «Конечный остаток» хранит последние известные числа перед исчезновением выезда из календаря. Порядок чисел соответствует экскурсиям и времени выездов в колонке «Остаток». У открытых выездов эта колонка содержит «—»; если Tripster явно показал ноль, сохраняется ноль. При повторном открытии используется новый фактический остаток, а при следующем закрытии фиксируется последнее известное значение.

«Чистое уменьшение с начала» сохраняется и после закрытия: начальный остаток минус последний известный остаток. Исчезновение выезда не добавляет продаж. Даты, которые уже прошли, также сохраняют конечный остаток и накопленное уменьшение.

Команда `python -m calendar_history.rebuild` восстанавливает таблицы обоих гидов и семи экскурсий из сохранённых снимков. Workflow выполняет её перед проверкой очередного интервала, поэтому старые закрытые даты исправляются даже при уже отправленном отчёте. Пересборка не обращается к Tripster, не отправляет Telegram и не меняет исходные снимки или квитанции доставки.

После полного сбора штатный бот отправляет общий отчёт по обоим гидам только при изменениях. При отсутствии изменений, а также при первом замере без сравнимого прошлого состояния Telegram остаётся тихим; все семь снимков и таблицы сохраняются как обычно.

Завершение интервала записывается в `data/calendar_history/joint/telegram/{observation_id}.json` со всеми семью турами. Для тихого замера квитанция содержит `completed_at`, `notification=suppressed_no_changes`, `changes_detected=false`, `delivery_required=false` и `delivery_complete=true`; фиктивного `sent_at` нет. При изменениях квитанция сохраняется только после подтверждённой отправки, с `notification=sent` и настоящим `sent_at`. Старые квитанции отправки остаются действительными. Повтор завершённого интервала не собирает данные и не отправляет отчёт заново. Внутренний контроль и Healthchecks принимают оба вида завершения, сохраняя проверку сроков.

Для каждой даты с изменениями у каждого гида отдельно показаны изменение с прошлого замера и накопленный итог с начала наблюдения за этой датой, например:

```text
04.12.2026:
Юлия — продано 2 места (всего 4)
Дмитрий — продано 0 мест (всего 0)
```

Общая строка «Всего» по двум гидам не выводится. Значение в скобках берётся из «Чистое уменьшение с начала» соответствующего гида; исходные замеры и начало наблюдения сохраняются. При отсутствии данных для накопленного итога показано «всего —».

Повторные попытки и резервный dispatcher используют тот же интервал, workflow и блокировку задачи 3. Основные UTC-часы GitHub Actions: 03:00, 06:00, 09:00, 12:00, 15:00, 18:00. GitHub может задерживать запуск. Последний новый интервал — 23:00; ночью новые замеры не создаются.

# Внешний контролёр семи задач Tripster

Контролёр tripster-external-watchdog выполняется в Cloudflare без обращения к GPT.
Cron запускает проверку каждые 15 минут. HTTP и preview URL выключены.
Рабочие настройки: MODE=recover, RECOVERY_ALLOWLIST=1,2,3,4,5,6,7.
Поставленная пользователем на паузу автоматизация ChatGPT не возобновляется.

## Что выполняется автоматически

Контролёр сверяет результаты в main с расписанием и повторно проверяет их перед
вмешательством. Если задача просрочена, он запускает её исходный GitHub workflow.
Он учитывает активные и ожидающие запуски и требует штатную очередь задачи.

Если сбор завершился, а запись результатов упала, повторяется только save job с
исходным непросроченным artifact. Успешный сбор и сообщения не повторяются.
Принятая GitHub команда ещё не означает восстановление: нужны свежие данные и
подтверждённая запись. Ошибки GitHub и неполные ответы запрещают вмешательство.

| № | Workflow | Подтверждение результата |
|---|---|---|
| 1 | daily.yml | 10 числовых счётчиков и отметка доставки за текущую дату |
| 2 | seats.yml | успешные проверки четырёх экскурсий моложе 90 минут |
| 3 | calendar-history.yml | общий отчёт семи экскурсий для текущего интервала |
| 4 | fx.yml | курс Wise и завершённая обработка ожидаемого интервала |
| 5 | closures.yml | семь экскурсий и сохранённое завершение моложе 90 минут |
| 6 | tickets.yml | успешная проверка билетов после 11:00 |
| 7 | monitor.yml в tripster-price-monitor | все 33 цены, безопасное состояние доставки и завершение моложе 45 минут |

Часы рассчитаны для Шымкента: Asia/Almaty, UTC+5. Задачам 1, 3, 4 и 6 даны
45 минут для штатного запуска. Календарь восстанавливается в своём двухчасовом
окне. Курс за 11:00 можно догнать до 20:00, за 20:00 — до местной полуночи,
как позволяет исходный скрипт; сохраняется реальное время получения котировки.

## Защита от повторов

Одна атомарная аренда и SQLite Durable Object сериализуют проверки. За один цикл
допускается одна команда восстановления. Между попытками одного сбоя выдерживается
45 минут, максимум две попытки на сбой и 96 за календарный день Шымкента.
Резерв попытки записывается до GitHub POST. Неизвестный результат не повторяется
слепо. Неподтверждённая доставка и отсутствие надёжной записи требуют разбора.

Утром 09.11.2026 обнаружено, что прежний общий лимит 12 включал также успешные
восстановления и был исчерпан уже к 05:45. Новый лимит покрывает суточные окна
всех семи задач при длительных пропусках штатного GitHub расписания. Резерв
попытки, лимит двух попыток одного сбоя и пауза 45 минут сохраняются.
Проверка не запускает здоровые задачи повторно.

Для задачи 7 нужна очередь tripster-task-7 и отметки
data/watchdog/completed.json и data/watchdog/status.json.
Контролёр сверяет все 33 идентификатора экскурсий. Старый зелёный workflow без
такой отметки не считается успешной проверкой. Если recovery_safe не подтверждён,
автоматический повтор блокируется. Журнал data/watchdog/runtime.json в репозитории
цен сохраняет резерв до Telegram POST, поэтому и обычный запуск по расписанию
не повторяет сообщение с неизвестным результатом отправки.

Контролёр выполняет подготовленные сценарии восстановления. Он не меняет код
мониторингов и не исправляет автоматически изменения сайта, неверные ключи или
неопределённую доставку Telegram. Такие случаи остаются заблокированными.
Существующие мониторинги, Healthchecks и резервный GitHub dispatcher сохраняются.

## Развёртывание и данные

Исходники и конфигурация находятся в этом репозитории. Deploy external watchdog
проверяет допустимые режим и allowlist и запрещает публичный интерфейс.
CLOUDFLARE_API_TOKEN используется только в GitHub CI. WATCHDOG_GITHUB_TOKEN —
fine-grained ключ двух репозиториев с Contents read и Actions write — передаётся
в зашифрованный secret Worker GITHUB_TOKEN. Значения ключей не выводятся.

Журнал последних 100 проверок и лимиты повторов хранятся в Durable Object.
Подробные состояния доступны владельцу в Cloudflare Logs; публичного endpoint нет.
Проверка рабочего режима не выгружает состояния задач в публичные артефакты.

## Проверки

node --test external_watchdog/test/*.test.mjs watchdog_verification/test/*.test.mjs

Изолированный live-тест восстановил только save; исходное выполнение сборщика,
его журнал и digest artifact не изменились. GitHub может скопировать успешный job
с новым ID при повторе. Поэтому проверяется runner, время и шаги выполнения,
а не равенство ID. Тестовый Cron и копия его ключа удалены.
Протокол: https://github.com/AntonioSkin/tripster-visitors-monitor/actions/runs/42506742499

Начальный режим observe и изолированный тест описаны в
watchdog_verification/README.md. Для возврата к наблюдению в конфигурации задаются
MODE=observe и пустой RECOVERY_ALLOWLIST. Действующие мониторинги и Healthchecks
при этом не отключаются.
